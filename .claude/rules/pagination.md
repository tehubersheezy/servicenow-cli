# Pagination (`--all`)

## Modules

- `src/query.rs` → ListQuery/GetQuery/WriteQuery/DeleteQuery → Vec<(String,String)>; encoded-query term splitting for keyset (`keyset_query`, `has_orderby`, `is_cursor_safe`)

`Paginator` (`client.rs`) has two modes behind one iterator; `table::choose_mode` picks one from argv alone, before `connect()`. Default output is JSONL (one record per line); `--array` buffers into a JSON array. Page size is whatever `--setlimit` sets (default 1000); `--max-records` caps total output (default 100,000; 0 = unlimited).

**Keyset is the default** (`client.paginate_keyset`, `KeysetPlan`). Each page is `<Q>^sys_id>CURSOR^ORDERBYsys_id` with `sysparm_no_count=true` + `sysparm_suppress_pagination_header=true`, and the cursor is the last record's `sys_id`. Every row that exists for the whole walk appears exactly once however the table changes (offset shifts and skips — the wiremock test demonstrates both), and there is no per-page `COUNT(*)`. Output is in `sys_id` order. **Offset** (`client.paginate`, following `Link: rel="next"`) is used for a query with its own `ORDERBY` (two sorts can't coexist; `--paginate keyset` plus `ORDERBY` is exit 1) or `--paginate offset`. Everything below was measured on dev421992 (Zurich, 2026-09-28):

- **`^NQ` gets the cursor in every segment; `^OR` gets it once.** A trailing AND term binds the whole `^OR` group (`a^ORb^sys_id>X` = `(a OR b) AND sys_id>X`, 36 of 71 rows = `sys_id>X` alone) but only the *last* `^NQ` segment (`a^NQb^sys_id>X` = `a OR (b AND sys_id>X)`, 52 = 44+8). A cursor appended once to an `^NQ` query never constrains the earlier segments, so each page returns them from the top again, and if one is bigger than a page the walk never advances. `query::keyset_query` rewrites the query into `a^sys_id>X^NQb^sys_id>X^ORDERBYsys_id` (36, correct); the single trailing `ORDERBYsys_id` sorts the whole union. #44's original plan had this backwards: it would have refused `^OR` and appended to `^NQ`. Terms are split on unescaped `^` (`^^` is a literal caret), and empty segments are dropped because a bare `sys_id>X` disjunct would match rows outside the filter.
- **A short page is not the end.** Row ACLs filter a page *after* the database fetched it. An `itil` user reading `sys_properties` gets 3 of 50 rows per page, and some whole pages come back empty with thousands of rows behind them. Under `no_count`, `X-Total-Count` is the number of rows the database **scanned for that page**, before ACLs: 50 on the 3-row page, 8 on the last partial page, 0 past the end, and exactly the limit on a full page (tried up to 30,000, so there is no server cap). The walk ends on the first page that scanned fewer than the limit. When a page scanned rows but returned none, the walk steps over them with `sysparm_offset` inside the cursor-bounded set. Without the header, only an empty page ends it.
- **No trailing probe, for speed.** A `sys_id>` range beside a selective filter lets the database walk the primary key to the table's end. The empty final probe of a 446-row `syslog` walk took 46s, while its one real page took 0.7s.
- **Canaries, because ServiceNow silently drops terms it can't evaluate.** A page that repeats any `sys_id` from the previous page proves the cursor was dropped, so the walk stops with `Error::Instance` (exit 2, pointing at `--paginate offset`) instead of looping. A record with no plain `sys_id` is handled by where it appears. A database view returns a synthetic `__ENC__<b64>=-<b64>=…` id (measured on `sp_page_widgets`), and a `--view` can omit the column. On the *first* page, before anything is written, that restarts the walk in offset mode (`KeysetPlan::fallback`). Later, it is a malformed page (seen once, on a `sys_properties` walk while the instance was overloaded; four reruns were clean). That is a resumable `Transport` error, with none of the bad page written. `--fields` without `sys_id` gets it appended on the wire and stripped from each record.
- **Offset needs the count, so it must not be suppressed.** `sysparm_no_count=true` *or* `sysparm_suppress_pagination_header=true` removes `rel="next"`, which made `--all --no-count` quietly stop after page one. An offset walk refuses both flags (exit 1). The issue's proposed "default `no_count` in Link mode" would have truncated every offset export. The offset iterator also loops over empty pages now, where it used to end at an ACL-emptied page that still had a next link.
- **Resume.** `Paginator::resume_token()` is the keyset cursor. The buffer drains before each fetch, so when a fetch fails every record up to the cursor is already on stdout. In JSONL mode `table::drain` wraps the failure in `Error::Interrupted { source, resume_from }`, which keeps the source's exit code and envelope and adds `resume_from`; `--resume-from <sys_id>` starts the walk there. Three failures are deliberately left unwrapped: `--array` failures (nothing was written), `Error::Instance` (the dropped-cursor canary, which a resume would trip again), and offset walks (an offset is a position, not a token). A 200 with no `result` array is a `Transport` error, not an empty page, because both modes end on "no more records" and would otherwise exit 0 on a mangled body.

`--all --output raw`, or `--all --output table` without `--array`, is a **usage error (exit 1)**, checked before `build_profile`/`build_client` so a pure argv mistake never reaches the network or an IdP. Table cannot size a column without seeing every row, so its message points at `--array`, which buffers and already renders; raw means "keep the envelope" and the paginator flattens every page's envelope into a record stream, so there is nothing left to keep — in the `--array` form either. Both were accepted and silently ignored before.
