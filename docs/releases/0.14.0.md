# sn 0.14.0

This release brings more of your ServiceNow work into the terminal: investigating flows, searching code, running scripts, and checking another user's access. It also adds more ways to sign in and lets you resume interrupted record exports.

## Troubleshooting without switching to the browser

**`sn flow`** lets you browse flows and subflows, read their steps, and review version history. For troubleshooting, you can find executions, inspect errors and logs, follow new runs, and check why a flow did not run for a particular record.

```bash
sn flow list --scope global
sn flow get sn_itsm.my_flow --outline
sn flow runs --record incident:INC0010001
sn flow debug <context_sys_id>
```

Flow definitions are read-only in this release. Execution details depend on your permissions and the instance's reporting settings; some step data is available only in the ServiceNow UI. The `why-not` checks use the record's current values, so they cannot fully reconstruct a past trigger.

**`sn codesearch`** finds text in scripts and code across application scopes. Narrow a search to one table or scope when you know where to look. Results follow your read permissions, and a warning calls out searches that may be incomplete.

```bash
sn codesearch MyUtil --table sys_script_include
```

**`sn doctor`** checks your identity and the roles, plugins, or properties a job needs. **`sn impersonate`** runs one command as another user, which helps investigate access problems. Impersonation requires the `admin` or `impersonator` role; doctor’s plugin and property checks require admin.

```bash
sn doctor --need-role itil
sn impersonate abel.tuter -- table get incident <sys_id>
```

## Scripts, decisions, and playbooks

**`sn script run`** runs server-side JavaScript and returns its output and errors as JSON. Supply a file, pipe a script through stdin, or write it inline. Application scopes are supported, and `--rollback` records changes for later rollback.

```bash
sn script run @maintenance.js --rollback --yes
```

This needs permission to run background scripts. `--yes` is required outside an interactive terminal. A client timeout does not stop the script on the instance, and `--rollback` does not automatically undo changes. There is no CLI rollback command yet. Script execution is unavailable inside `sn impersonate`.

**`sn decision`** lets you inspect decision tables and evaluate them with supplied inputs. It checks input names and values before running. Editing, importing, and evaluating drafts are not included yet; Decision Builder and an appropriate role are required.

**`sn playbook`** lists a record's playbook executions and starts new ones. `trigger --only-if-none` skips starting a playbook when the record already has any execution, including a finished or cancelled one. The Playbook Experience application is required. The separate `launch` command is included, but has not yet been verified successfully on a live instance.

## More login options

For unattended jobs, `sn` now supports **JWT-based OAuth** using a local private key and **externally issued tokens** supplied through stdin or a command such as a secrets-manager lookup.

Browser login can also use the ServiceNow SDK's public OAuth client when it is active on your instance. This removes the initial client-registration step and asks you to paste a code from the browser. Registering your own OAuth client is still recommended for ongoing use.

See the [setup guide](../setup.md) for configuration instructions.

## Exports and everyday shortcuts

**Bulk exports can resume after an interruption.** `sn table list --all` now pages by `sys_id` by default. An interrupted JSONL export can include `resume_from` in its error; use that value with `--resume-from`, keeping the same query and fields. Resume is unavailable for buffered `--array` output and offset pagination. An export is still a read of a changing table, not a snapshot.

**Offline schema lookups and shell completion** are available through `sn cache`. Build the cache once, then use it for table and column names without a network request. Column indexing requires admin; other accounts get table names only. Refresh it after schema changes.

```bash
sn cache refresh
sn cache columns incident
sn completion bash --dynamic
```

Load the generated completion script in your shell to enable suggestions. Dynamic completion is optional and has been tested in bash; static completion remains the default.

Two smaller conveniences round out the release: **`sn open incident`** opens a table's list view, with `-q` for filtering, and **`sn get`** can look up custom record-number prefixes when your account can read `sys_number`. Profile output now shows stored proxy and TLS settings, with proxy passwords masked.

## Before you upgrade

- **Export order changes.** `sn table list --all` returns records in `sys_id` order. An `ORDERBY` query clause selects offset pagination; `--paginate offset` also keeps the previous pagination method. Offset exports reject `--no-count` and `--suppress-pagination-header`.
- **Malformed export responses now fail.** A response missing its record array exits 3 instead of ending successfully. Error objects can include `resume_from`; `status_code` may be absent for an impersonation permission refusal reported inside a successful HTTP response.
- **Keep connection settings when replacing profiles.** `sn profile add --force` resets proxy and TLS options to the flags supplied. Repeat the proxy and certificate flags you want to retain. Omitting `--insecure` restores verification unless another setting, such as `SN_INSECURE`, enables it. `sn init` continues to preserve omitted settings.
- **OAuth profiles need fresh tokens after replacement.** For browser-based OAuth, run `sn profile login` again.
- **Record lookups can report a more specific table.** A bare-number `sn get` now reads the record from its own class. Use an explicit `table:number` reference if your script needs to keep the named table.

If you generate agent or MCP tools from `sn introspect`, regenerate them to pick up the new commands and flags.
